# 振り返り：PR #1（ADR 0001 開発言語の選定）

## 日付
2026-11-26

## Keep（良かった・続ける）
- ブランチ → commit → push → Pull Request → レビュー → Approve → merge を、
  承認者（妻）を立てて実際に一通り行えた
- 差し戻し（Request changes）→ 修正 → 再レビュー → Approve の流れを体験できた
- `git add` と `git log --oneline --graph` は理解できた。特に --graph は
  ブランチとmergeの関係が見えるので、認知負荷が大きく下がった

## Problem（問題）
1. GitHub上で「今、自分がやるべきこと」の一覧が見つからない（作成者・承認者の両方）
2. 承認者のコメントのしかたによって、Files changed では作業できず、
   Conversation を探し回る必要があった（指摘した行を直すと、指摘が Outdated になり
   Files changed から見えなくなる）
3. 手順の説明に、誤り・画面の指定漏れ・枝葉への脱線があり、理解が定着しなかった
4. Gitの基本概念（commit・ステージ・ブランチ・merge）の全体像がまだ曖昧
5. merge後のブランチの削除が手作業で、意味が分かりにくい
6. 基本的なGitのコマンド（restore など）を覚えていない

## Try（次に試す）
1. やることの一覧：
   - 作成者・承認者とも、「Pull requests」画面の左側の「Inbox」を入口にする
   - 次のPRで実際に使い、足りなければ別の方法を検討する
2. 承認者が指摘を確認する方法：Conversation で Ctrl + F「Resolve conversation」
3. 説明の改善：Project の指示に「質問への答えを1行目に」「各手順に今いる画面とタブを書く」を追加済み
4. Gitの概念：次のPRでも同じ流れを繰り返し、git lg で毎回付箋の位置を確かめる
5. ブランチの削除を自動にする：
   - GitHub側：mergeしたら下書き版を自動で消す設定を入れる
   - PC側：git pull のときに、消えた下書き版の付箋を自動で片付ける設定を入れる
6. よく使うGitのコマンドの一覧を作り、リポジトリに置く
