# 0001 開発言語の選定

## ステータス
承認済み（2026-11-17）

## 背景
- 簡易なWebアプリ（×4）を作成した後、職場で作成したToDo管理アプリを再現する
- 作成者はWeb開発言語の経験なし、Python経験あり
- 実装はClaude Codeが行い、作成者が設計とレビューを担当する（AI駆動開発）

## 選択肢
- 案1：TypeScriptで統一（画面側・サーバー側ともTypeScript。サーバーはNode.jsで動かす）
- 案2：画面側はTypeScript、サーバー側はPython
- 案3：JavaScriptで統一（型なし）
- 案4：Pythonで統一（画面はサーバー側で作って送る）

## 決定
案1：TypeScriptで統一

## 理由
- 画面側とサーバー側でやり取りするデータの型を1か所で定義できる。
  案2では定義が2つの言語に分かれ、片方だけ修正されて食い違いが起きやすい
- 型の食い違い（存在しない項目名、数値と文字列の取り違え、空の値の扱い漏れなど）の
  検出をTypeScriptのコンパイラ（tsc）に任せ、作成者はロジック・仕様の確認に集中できる。
  案3では型がないため、この検出ができない
- 案4では、学習目的である非同期通信・API設計を扱う機会が減る。
  また、Pythonの型ヒントは標準では検査されない
- Web開発で広く使われており、情報やライブラリが多い

## 不利な点
- Pythonの経験を活かせない
- 型の書き方を覚える手間がある

## 影響
- 全アプリで同じ言語・同じひな形を使う
- 開発するPCにNode.jsが必要（v24を確認済み）
